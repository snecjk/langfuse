# Proposal

## Why

当前产品界面主要使用硬编码英文，中文用户理解导航、操作和提示的成本较高。引入简体中文与英文切换，在不改变业务数据和 API 契约的前提下提供完整的中文使用体验。

## What Changes

- 提供 `zh-CN` / `en` 两种界面语言，首次默认简体中文；显式选择保存在当前浏览器，刷新和重新登录后沿用。
- 登录页与应用公共区域提供语言入口，切换不改变当前 URL、查询条件、项目或未提交输入。
- 建立类型安全翻译字典、参数插值和英文回退机制，按公共界面、核心业务、设置及企业界面的顺序迁移所有第一方产品 UI。
- 日期、相对时间、数字及 HTML 语言标记随语言更新；不改变时区、金额币种或实际数值。
- 不翻译用户数据、提示词、模型名、API/数据库字段及枚举值、日志、SDK、导出机器字段、外部文档、服务端邮件和第三方托管页面。服务端原始错误保留，通过稳定错误码提供可翻译的界面提示。
- 分批交付便于审查，但整个变更完成的标准是范围内界面迁移完成，而不只是增加语言按钮。

### 全量范围与边界

“全量”指当前版本全部第一方产品界面，包括可达的旧版页面、角色受限页面、功能开关页面和企业页面；不是只翻译入口标题，也不是只翻译开发者当前账号能看到的功能。

| 范围 | 必须纳入的界面 |
| --- | --- |
| 公共界面 | 导航、命令菜单、通知、引导、帮助、通用表格、筛选器、列显示、导出、对话框及无障碍标签 |
| 身份与工作区 | 登录注册、密码/验证、错误页、SSO/Hugging Face 专用流程、组织/项目选择与创建 |
| 分析与可观测性 | 首页、仪表盘与 widgets、追踪/观察、会话、用户、详情面板及 JSON 查看器的系统工具栏 |
| 内容与实验 | 提示词、数据集、条目、运行/对比、实验、Topics、Skills、试验场及其编辑/导入/管理流程 |
| 评估 | 评分、分析、当前与可达旧版评估器、模板、规则、代码/模型评估编辑器、人工标注 |
| 网关与后台操作 | AI Gateway 的配置/密钥/分析/引导、批量操作、批量导出及任务状态 |
| 设置与企业 | 账户/项目/组织、成员邀请、API/LLM 密钥、集成、数据保留、SSO、账单、审计、管理员和迁移界面 |

系统自带说明、占位符、验证和可预期错误、加载/空/无权限/失败/成功状态均在范围内。上述每组包含列表、详情、新建、编辑、导入、删除/转移等实际存在的流程；不凭空新增产品功能。

品牌、专业标识及机器字段可按有理由的例外保留。原有排除项继续有效：用户内容、协议/API/数据库值、诊断日志、SDK/代码示例、机器导出、外部文档、服务端邮件及第三方托管页面不翻译；第一方页面包裹它们的按钮和说明仍需翻译。

### 完成标准

- 建立覆盖当前路由、实际渲染组件和交互状态的清单，每行分别记录源码迁移与运行验证，不以模块标题代替完整覆盖。
- 清单内所有可译界面文案均有中英文实现；没有未处理、未分类的硬编码英文，也没有用英文回退掩盖的未完成项。
- 为残留英文提供可审查的例外理由；译文数量、通过测试的数量和总任务勾选数均不是覆盖率。
- 增加源文案遗漏与字典完整性两道检查，并验证语言切换、业务契约隔离和真实生产产物。分批提供开发模式预览，但不以预览可用替代全量验收。

## Capabilities

### New Capabilities

- `interface-localization`: 界面语言选择与持久化、文案翻译与回退、本地化格式和业务契约隔离。

### Modified Capabilities

无。现有 OpenSpec 尚无能力规范。

## Impact

- 主要影响 `web/src/pages/_app.tsx`、`web/src/pages/_document.tsx`、公共布局、导航、认证页、各业务 UI、日期与图表格式化工具及企业 UI。
- 当前 `web/next.config.mjs` 仅声明英文 locale；方案保留现有 URL，不增加语言路径前缀。
- 增加 web 内部翻译基础模块和双语资源；不需要数据库迁移、后端语言字段或公共 API 变更。
- 首屏语言一致性涉及服务端渲染与静态优化，需要以真实生产构建验证；翻译资源按功能组织，避免不必要的首屏体积增长。
