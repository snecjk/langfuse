# Proposal

## Why

当前产品界面主要使用硬编码英文，中文用户理解导航、操作和提示的成本较高。引入简体中文与英文切换，在不改变业务数据和 API 契约的前提下提供完整的中文使用体验。

## What Changes

- 提供 `zh-CN` / `en` 两种界面语言，首次默认简体中文；显式选择保存在当前浏览器，刷新和重新登录后沿用。
- 登录页与应用公共区域提供语言入口，切换不改变当前 URL、查询条件、项目或未提交输入。
- 建立类型安全翻译字典、参数插值和英文回退机制，按公共界面、核心业务、设置及企业界面的顺序迁移所有第一方产品 UI。
- 日期、相对时间、数字及 HTML 语言标记随语言更新；不改变时区、金额币种或实际数值。
- 不翻译用户数据、提示词、模型名、API/数据库字段及枚举值、日志、SDK、导出机器字段、外部文档、服务端邮件和第三方托管页面。服务端原始错误保留，通过稳定错误码提供可翻译的界面提示。
- 分批交付便于审查，但整个变更完成的标准是范围内界面迁移完成，而不只是增加语言按钮。

## Capabilities

### New Capabilities

- `interface-localization`: 界面语言选择与持久化、文案翻译与回退、本地化格式和业务契约隔离。

### Modified Capabilities

无。现有 OpenSpec 尚无能力规范。

## Impact

- 主要影响 `web/src/pages/_app.tsx`、`web/src/pages/_document.tsx`、公共布局、导航、认证页、各业务 UI、日期与图表格式化工具及企业 UI。
- 当前 `web/next.config.mjs` 仅声明英文 locale；方案保留现有 URL，不增加语言路径前缀。
- 增加 web 内部翻译基础模块和双语资源；不需要数据库迁移、后端语言字段或公共 API 变更。
- 首屏语言一致性涉及服务端渲染与静态优化，需要以真实生产构建验证；翻译资源按功能组织，避免不必要的首屏体积增长。
