# Design

## Context

参见 proposal.md 的动机、全量边界和完成标准。项目使用 Pages Router，已有 `web/src/features/i18n/` 字典层、provider、Cookie 解析和部分模块接入；`_app.tsx` 与 `_document.tsx` 已共享请求语言。Next 路由配置仍只有英文，但界面语言独立于路由 locale，不增加 URL 前缀。

当前源码仍有未迁移的实际界面，例如追踪详情的 Formatted/Raw、PasswordInput 的 Show/Hide password、Topics 配置、批量导出及企业 SSO；数字和图表工具也有固定 en-US。现有资源检查仅遍历已收录的字典，不能发现这些硬编码遗漏。`coverage.md` 是部分实施及验证快照，不能当成全量完成证据。

本次修订保留已实施基础，不重建 i18n、不更换框架，也不以原任务完成数或历史译文数量推算覆盖率。

## Goals / Non-Goals

**Goals:** 在保持 URL 和业务契约稳定的前提下，实现可逐功能迁移、可验证、首屏一致的双语 UI。

**Non-Goals:** 账户跨设备同步、自动翻译用户内容、根据浏览器语言自动决定首次语言、改造为 App Router、改变后端原始错误/邮件或第三方页面。

## Decisions

### 1. Web 内部集中式翻译层

在 `web/src/features/i18n/` 提供 locale 白名单、纯函数解析器、类型化 key、参数插值和 React provider/hook。英文资源定义完整 key 类型，中文资源按相同结构组织并允许运行时英文回退；发布前检查范围内 key 的双语完整性。按 common/auth/navigation/tracing/prompts/datasets/evaluations/settings 等命名空间拆文件，核心资源同步可用，业务资源按页面模块导入，避免所有页面引入全部词典。

先使用小型内部字典层，不引入外部翻译平台或运行时自动翻译。选它是因为当前明确只有两种语言及有限插值需求；拒绝对 DOM 做文本替换，这会破坏 React 与业务数据边界。涉及计数时使用显式单复数消息及 `Intl.PluralRules`；插值只产生字符串/React 文本，不接受任意 HTML。开发时缺少英文 key 抛出明确错误，生产端最终回退通用可读错误消息并记录 key，不把 key 暴露给用户。

### 2. 浏览器 Cookie 偏好与原址切换

使用独立 `langfuse-ui-locale` Cookie，白名单仅 `zh-CN` / `en`，无效或缺失均解析为 `zh-CN`。Cookie 使用 Path=/、SameSite=Lax、有效期一年，HTTPS 下 Secure；不包含身份信息，需客户端可写。写入失败时仍在当前页面更新语言，但不承诺被浏览器禁止的持久化。

provider 接收已解析初始语言；切换只更新上下文与 Cookie，不触发 router.push、页面重挂载或表单重置。登录布局与应用公共区域使用同一个选择器，先查找 design-system 中适合的菜单/选择组件。保存的是浏览器偏好，不写数据库。相比 localStorage-only，Cookie 可参与 SSR，避免英文闪烁；相比语言 URL 前缀，不影响深链接、认证回调与查询参数。

### 3. 服务端与客户端共享初始语言

在 `_app` 服务端初始化路径解析 Cookie 并将 locale 序列化到页面初始 props；使用 App 的 getInitialProps 时保留 Next 原有页面 props 获取链，不丢失既有 getServerSideProps 的输出。`_document` 用同一 resolver 设置 HTML lang；客户端从序列化值初始化，切换同步更新 document.documentElement.lang。

该方案可能关闭部分页面的自动静态优化，这是为了正确的每请求语言首屏而接受的代价。显式 getStaticProps 页面不能依赖每请求 Cookie：实施时将需要翻译的此类产品页改为请求期渲染，保持业务取数语义，并以构建路由清单确认没有残留冲突。现有 Next i18n 路由设置不扩展 zh 前缀，界面语言不依赖 router.locale。

响应不得跨语言共享 HTML 缓存：保留认证页面的私有响应策略，对新增请求期语言页面设置 private/no-store，避免 CDN 缓存串语言。客户端路由进入新页面时沿用 provider 当前语言，不被旧的 pageProps 覆盖。不要在服务器使用全局可变 locale，避免并发请求串语言。

### 4. 标签与业务值分离

静态导航与列定义保存 labelKey，或在 hook/渲染函数中调用翻译器；语言变化必须使相关 memo/列头/验证消息重新计算。URL、表格列 ID、枚举值和 API payload 不使用译文。浏览器可预期错误按稳定错误码映射翻译，无法识别的服务端错误保留原始诊断文本。

日期与图表格式化显式接收 locale，采用现有日期工具可支持的中文 locale 及 Intl 格式化；沿用既有时区、币种、精度和排序的原始值。不要全局替换代码中的 `en`，避免误改协议和模型标识。

### 5. 按模块迁移，最终完整验收

维护术语表：Trace=追踪、Observation=观察、Prompt=提示词、Dataset=数据集、Score=评分；专业名称必要时保留英文。覆盖公共组件、认证、核心业务、设置、当前可用企业界面及可访问名称；不改 API 文档示例、用户 JSON 或外部内容。每批记录已迁移页面清单和明确排除项。最终检查 UI 字面量与资源完整性，人工区分业务数据和可译文案，不能简单以存在英文字符判定失败。

### 6. 路由—组件—状态清单作为完成依据

实施时扩充现有 `coverage.md`，保留历史检查记录，并为每个路由/实际渲染 owner 建立条目。每行记录：模块、路由或入口、源文件、角色/开关条件、实际存在的子流程与状态、资源命名空间、源码迁移状态、验证方式/结果和非翻译内容理由。状态分别为“未迁移/部分迁移/源码完成”与“未验证/已验证/不适用”，不能合并成一个模糊的完成标记。

清单需从 pages/app 产品路由与导航、feature、components、web/src/ee 和 ee 的实际 UI 消费关系核对；排除 API handlers、测试/stories、构建生成文件和日志。共享包中提供给 UI 的固定标签/验证说明也需追踪到显示位置，不得全局翻译后端诊断或枚举。路由并非全部入口，还要追踪弹窗、抽屉、编辑器、命令菜单、通知和权限/功能开关分支。

每个大模块按实际 owner 和流程拆任务；清单内发现新的第一方页面必须归入同一变更，不得因为原任务列表未点名而默认忽略。不适用仅限组件确无该状态，须注明依据；缺权限、缺服务或缺浏览器属于未验证，不是不适用。源码已部分接入的模块仍保持未完成，直到其清单项全部满足要求。

### 7. 两道检查与有依据的英文例外

保留字典完整性检查，补充词法/AST 级文案审计：定位 JSX 文本、展示属性（含 aria/title/placeholder）、静态列头/菜单/帮助配置、表单验证及面向 UI 的通知/错误；不使用“源码出现英文字符”这种会误伤协议的判据。审计输出源路径、位置、上下文与分类；它是候选项检测，不声称静态扫描能证明所有运行分支都已覆盖。

第一道门禁检查双语 key、插值参数、空值、计数模板及有效的页面命名空间装配；第二道门禁发现新增可译硬编码与未分类候选。例外清单以具体位置/语义及理由区分品牌、模型/机器标识、代码示例和用户数据入口，不用整目录忽略、宽泛正则或 ESLint 禁用压掉遗漏。历史扫描基线只用于排期，不能成为永久豁免；最终范围内可译候选必须清零或迁移，例外须人工复核。

将检查接入稳定的 package 命令和 CI，验证时先用一个临时的真实 JSX/列头漏翻样例证明它会失败，再恢复样例并通过。字典检查通过但弹窗仍英文时必须阻止模块验收。预期的临时英文回退只保留运行时容错，不为发布提供豁免。

### 8. 完整消息、共享控件和动态错误

共享 design-system 组件保持 context-free：显式接收可翻译 labels，并由应用 wrapper/调用方提供语言；同步迁移所有实际应用值导入，不能只给组件增加 labels 而遗漏消费者。确认图标按钮、密码显示开关、搜索、日期选择器和第三方控件可配置的系统 chrome；第三方无法本地化的用户可见系统文案须提出明确替代方案，不静默排除。

复合句和计数消息按完整语义建 key，而不是翻译零散英文片段后拼接。需要链接、强调等 rich text 时使用受控 React 插槽/组件组合，让译文能调整语序；插值内容始终作为文本或受控节点，不接受任意 HTML。保留原验证规则，状态存储错误码/稳定 key 与原始诊断，渲染时按当前 locale 映射；已有错误和通知需要切换后更新，不能只翻译未来新触发的消息。

### 9. 格式化、分层验证与交付节奏

普通数字、金额、相对时间、日期选择器和图表的 locale 从当前界面显式传递。图表按既有 prepare → visualise 契约在准备层决定格式，渲染层不重复推断；不改变时区、币种、精度、排序和原值。截图和比较使用同一合成数据与固定时间，避免把格式变化误当数据变化。

先完成一个清单子范围的代码、资源检查、适用的轻量行为回归和清单记录，再提供开发模式预览；不为每条标签新增测试，也不把所有验证拖到最后。状态保留、验证错误、payload、权限/路由等风险用最近现有套件覆盖，新增测试须能在缺少实现时失败；已有 story 的组件在原 story 扩展。每个模块在源码完成后做一次有代表性的中英文浏览器检查，最终再统一验收跨模块、移动端和生产运行时。

开发预览、生产产物和 Docker 交付分开记录：默认 Compose 预构建镜像不能证明本地源码有效；最终用本地源码构建的产物/镜像核验，不改变既有数据卷、不运行隐式数据重置。完整门槛保留 lint/typecheck/knip、生产构建、client-bundle scan 及 seed CLI 场景。Cargo/浏览器缺失和仓库基线问题单列；未跑、失败、缓存命中均如实记录，不能把阻塞或跳过写成通过，修复超出本变更范围时另行申请。

## Risks / Trade-offs

- [每请求渲染增加服务端成本] → 对照生产构建路由清单和首屏响应；避免为了读取 locale 重复请求业务数据。
- [中文长度导致菜单/表格挤压] → 验证窄屏、折叠侧边栏、弹窗与英文长文本，不写仅适合一种语言的固定宽度。
- [静态标签或 memo 不更新] → 迁移为翻译 key/响应式计算；用带未提交输入的语言切换检查捕获回归。
- [业务命名空间漏装导致闪烁] → 当前页面所需资源在首屏与客户端首次渲染前均可用，不在 hydration 后才加载首屏词典。
- [英文回退掩盖遗漏] → 回退用于可靠性；发布验收要求范围内资源齐全，并记录审查结果。

## Migration Plan

先交付基础模块与公共切换入口，再按公共界面、核心业务、设置/企业界面迁移，每批保持中英文可用。没有数据库迁移。依照现有 seed CLI 准备合成数据，不写临时原始数据脚本。最终在生产构建运行时检查 SSR、深链接、认证跳转、状态保留与布局。回滚恢复原组件文案与 provider/入口/文档初始化，废弃 Cookie 无业务副作用，不需要数据回滚。

## 完成定义与进度继承

原 1.1、1.2、1.3、2.1、2.4、4.1 的已完成记录保留；它们仅证明相应基础能力，不证明模块或生产端已经全量完成。原 3.1–3.5 的未完成大项由细化的模块任务接替，原 4.2 拆为数字、图表和日期控件；新增工作均保持未勾选。任务总数变化是拆分结果，不应解释为实施进度倒退或完成百分比。

最终交付同时满足：完整清单覆盖所有范围内入口/状态；无未处理的可译英文/缺失中文；中文与英文均可用；例外有依据；用户数据、业务提交值与权限不变；生产运行验证通过。词条数、截图数量、HTTP 200 或单测总数均不能单独替代这些条件。
